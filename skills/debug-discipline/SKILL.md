# Debug Discipline — 调试升级纪律（主 agent 先调试，2 轮失败委派 IIC）

**定位**：主 agent 有最全面上下文，是首选调试者，应放手自行调试。本 skill 的目的是**守住升级闸门**——当主 agent 两轮以上解决不了时，强制停止盲目推进，委派 IIC 独立调查。

**触发条件（可计数，非语义判断）**：
- ✅ 第 2 次修复失败（改了 2 次，复现测试仍 RED）
- ✅ 连续两轮无进展（改了 N 次但症状没变 / 没找到根因）
- ✅ 用户明确要求（"换个角度看看" / "请独立调查"）
- ❌ 第一轮调试（主 agent 自己查，不需要 skill）

**核心原则**：不干预主 agent 的自主调试，只在它"卡住"时介入。这样既保留主 agent 的上下文优势，又用"数到 2 就停"的硬规则破除盲目推进。

## 调试流程

```
收到 bug / 测试失败
  → ① 主 agent 自行调试（有全上下文，放手让它查）：
       - 写复现测试（最小化，RED）
       - 开轻量 Debug Journal（假设/证据/失败原因，几行即可）
  → ② 第 1 次修复失败 → journal 记录失败证据
  → ③ 第 2 次修复失败 / 连续两轮无进展 → 【强制触发】停下，委派 IIC
  → ④ IIC 独立调查：亲自复现 + 独立根因 + 判别性验证步骤 + 候选修复方向
  → ⑤ 主 agent 执行 IIC 的验证步骤 → 实施修复（代码归主 agent）
  → ⑥ 验证证伪 → 携新证据回 IIC（R2）→ 仍未一致 → R3 升人工
```

## ① 主 agent 自主调试（不需要 skill）

- 写**最小化**复现测试（不是整个场景），精确复现用户描述
- 复现测试失败（RED）确认 bug 存在后，才进入分析
- 无法复现 → 向用户提问（参数/操作序列），不要猜测
- 开轻量 Debug Journal：每轮记几行（假设/改动/结果/失败原因）即可，不必完整文档

## ② Debug Journal（轻量，为主 agent 和 IIC 服务）

主 agent 自主调试时**顺手记**（不是重负担），每轮几行：

```
## 第 N 次尝试
- 假设：<根因假设>
- 改动：<改了哪里>
- 结果：<复现测试输出>
- 失败原因判定：<假设错误 / 改动没对准 / 证据不足>
```

**作用**：
- 给主 agent 自己：计数看得见、打断锚定（"第 1 次就想改这里失败了"）
- 给 IIC：第 2 次失败时，IIC 读 journal 才能发现主 agent 锚定在哪个错误前提
- 修完后：journal 是 BUG-LEDGER / post-mortem 的素材

## ③ 轻量 GATE（主 agent 自主调试时的底线）

主 agent 自主调试不设重闸，但守住两条底线：
- **每轮只测一个假设**——别一次改三处然后说"看看哪个生效"
- **改的是"症状"还是"根因"？** 回答不了就先不要改（这条在 journal 里写清楚即可）

## ④ 第 2 次失败或僵局 → 委派 IIC（核心升级闸门）

当第 2 次修复失败，或调试陷入僵局（改了多轮无进展）时，**强制停下**，委派 IIC：

```
task(
  subagent_type: "iic",
  description: "IIC investigate <bug>",
  prompt: "请独立调查 bug：<描述>。
  - 项目根目录：<绝对路径>
  - 复现测试：<绝对路径>
  - Debug Journal：<绝对路径>
  - 宪法文档：<绝对路径>（如 PRD/architecture/detailed-design）
  请按 IIC 流程：亲自复现 → 审查 journal → 独立根因分析 → 判别性验证步骤 → 候选修复方向。
  你不改代码，验证步骤由我执行。"
)
```

- IIC 返回后，**执行它的验证步骤**，把结果写回 journal
- 验证确认它的假设 → 主 agent 实施修复（代码归主 agent）
- 验证证伪 → 携新证据回 IIC（R2），仍未一致 → R3 升人工
- IIC 是"调查"，你（主 agent）是"实施"——**调查权与实施权分离**，这是核心纪律

## 硬性检查

- 第 1 次修复失败：journal 记录失败证据了吗？第 2 次会记得触发升级吗？
- **第 2 次失败：必须停下委派 IIC，不能继续改**（这是硬闸门，不是建议）
- 声称"修好了"前：复现测试 GREEN 了吗？journal 里有失败证据和最终根因吗？

## 注意

- Debug Journal 在调试中是**工作产物**（消费即弃），不触发 docs-review；**修完后**才正式化为 post-mortem / BUG-LEDGER 条目
- IIC 报告是工作产物，消费即弃，不触发 docs-review
- 不要把 IIC 当"第二个主 agent"——它只调查提方案，不改码；改动全在你
- 若 IIC 幻觉（无证据断言），在回环里点出并附证据
