# Docs Review — 文档审查委派（产出即审 + 商讨回环）

主开发模型写出的文档存在盲区（同族模型思维惯性）。本 skill 规定：**任何项目产出的意图/事实类文档，产出后必须 review**，且 review 是"反馈回路"——产出 → 审查 → 主 agent 思考采纳/否决 → 争议回环商讨 → 一致性文档交人工。

## 触发规则（产出即审）

- **必审**（意图/事实类）：spec、plan、宪法文档（PRD/architecture/detailed-design）、阶段报告、能力边界记录、BUG-LEDGER、测试报告、提交前要对齐的文档。
- **判断跳过**（临时产物）：temp 脚本、POC 测试、一次性 SVG、tmp 文件——主 agent 自行拿捏。
- **时机**：文档"写完了"（声称完成/提交前）触发一次。每份文档完成版审一次，中间编辑版不审（防疲劳）。只有重大返工才需要二轮 review。
- **常态化**：plan 完成后、文档更新后、每 N 次 commit 后，主动检查是否有未审文档。

## 委派步骤

1. 调用 `task` 工具（`subagent_type: "docs-review"`）：
   - `description`: 简短语（如 "review sprint plan"）
   - `prompt`: 待审文档**绝对路径** + 审查范围（核对测试数/模块路径/物理公式/完成状态/全面）+ 背景上下文
2. `docs-review` 返回结构化审查报告（发现按严重度分级，每条带 `文件:行号` 证据）。

## 三级裁决 + 商讨回环（核心协议）

拿到审查报告后，**主 agent 对每条发现分类**：

| 分类 | 含义 | 处理 |
|------|------|------|
| **① 采纳** | 发现成立 | 修改文档 |
| **② 否决-无争议** | 明显错误/无关/与任务无关的小问题 | 直接驳回，**不进商讨** |
| **③ 否决-有争议** | 物理公式 / 架构决策 / 核心事实（影响正确性或方向） | 进入商讨回环 |

**商讨回环（仅 ③ 进入）**：
```
R2: 把主 agent 的否决 + 反驳证据 送回 docs-review
    reviewer 看到新证据后：认输（撤回）或 用更强证据再断言（坚持）
R3: 仍未一致的 → 升到人工（两边立场 + 证据并排）
```

**守卫**：
- **证据门控**：每轮发言必须带 `文件:行号` 或精确推导。**无新证据的坚持直接作废**（拦住耍赖式反驳 + reviewer 幻觉式断言）。
- **轮次上限**：最多 R1→R2→R3。R3 不一致不硬压，直接升人类。
- **分级商讨**：只有 ③ 进回环，控制延迟与成本。

**完成后**：
- 一致性文档（含未决争议清单）→ 交人工最终 review
- 人类是最终裁决者：商讨结果仍是候选，人工可推翻

## 示例

```
task(
  subagent_type: "docs-review",
  description: "review phase10 plan",
  prompt: "请审查 D:\\my code\\phi_emu\\docs\\superpowers\\2026-08-01-PHASE10-SPRINT-B.md。
  审查范围：1) 与当前代码的漂移（测试数/模块路径/接口） 2) 物理公式正确性
  3) 边界测试覆盖 4) 内部矛盾。项目根目录 D:\\my code\\phi_emu，宪法文档在 docs\\superpowers\\。"
)
```

## 注意

- review 定位是**意图层**（文档对不对）早期预警；测试负责**实现层**（代码对不对）。两者互补，不替代。
- 子代理只审查不修改（edit/write 已禁）。发现的问题回到主流程修。
- 若发现子代理幻觉（无依据断言），在回环里点出并附证据，它下次更严格。
